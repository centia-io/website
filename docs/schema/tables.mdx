# Tables

A table stores your data as rows under a fixed set of named [columns](./columns.mdx), each with a PostgreSQL data [type](../types.mdx). Tables live inside a [schema](./schemas.mdx) and are addressed as `schema.table` throughout Centia.io.

The Table API is the provisioning interface for tables: it creates a table, optionally with nested columns, [indices](./indexes.mdx) and [constraints](./constraints.mdx) in one request, reads its definition, renames it or moves it to another schema, and drops it. Once a table exists you read and write its rows with [SQL](../statement.mdx), GraphQL or the [Feature API](../features.mdx), and a table with a geometry column is automatically available as a map layer through the [OGC services](../ogc/services.mdx). Use this API from migrations, CLI scripts or the Web App when you need to change the structure of your data rather than its content.

## Add table

A new table object can be empty (name is the only property) or contain nested columns, indices and constraints.

<Tabs>
    <TabItem value="webapp" label="Web App">
        ![Create table in the Centia Web App](/img/screenshots/webapp-placeholder.svg)
    </TabItem>
    <TabItem value="http" label="HTTP" default>

        ```http title="Create new empty table"
        POST https://api.centia.io/api/v4/schemas/rockhall HTTP/1.1
        Content-Type: application/json
        Authorization: Bearer abc123

        {
            "name": "inductees"
        }
        ```

    </TabItem>
    <TabItem value="cli" label="CLI">

        ```bash
        centia table add "rockhall" "inductees"
        ```


    </TabItem>
</Tabs>

## Get table

You can either get a single table or a collection of tables. The schema object contains all nested objects like
columns, indices and constraints. Use the `namesOnly` parameter to omit nested objects.

<Tabs>
    <TabItem value="webapp" label="Web App">
        ![View tables in the Centia Web App](/img/screenshots/webapp-placeholder.svg)
    </TabItem>
    <TabItem value="http" label="HTTP" default>

        ```http title="All tables, names only"
        GET https://api.centia.io/api/v4/schemas/rockhall/tables?namesOnly HTTP/1.1
        Accept: application/json; charset=utf-8
        Authorization: Bearer abc123
        ```

        ```http title="Specific tables"
        GET https://api.centia.io/api/v4/schemas/rockhall/tables/inductees,anothertable HTTP/1.1
        Accept: application/json; charset=utf-8
        Authorization: Bearer abc123
        ```

    </TabItem>
    <TabItem value="cli" label="CLI">

        ```bash
        centia table get "rockhall" "inductees"
        ```

    </TabItem>
</Tabs>

## Rename and move table

You can move a table to another schema by setting the `schema` property and renaming the table by setting the
`name` property.

<Tabs>
    <TabItem value="webapp" label="Web App">
        ![Rename and move table in the Centia Web App](/img/screenshots/webapp-placeholder.svg)
    </TabItem>
    <TabItem value="http" label="HTTP" default>
        ```http
        PATCH https://api.centia.io/api/v4/schemas/rockhall/tables/inductees HTTP/1.1
        Content-Type: application/json
        Authorization: Bearer abc123

        {
            "name": "members",
            "schema": "rock_roll_of_hall"
        }
        ```
    </TabItem>
    <TabItem value="cli" label="CLI">
        ```bash
        centia schema rename "rock_roll_of_hall" "inductees" "members"
        ```
        ```bash
        centia schema move "rock_roll_of_hall" "inductees" "members"
        ```
    </TabItem>
</Tabs>
