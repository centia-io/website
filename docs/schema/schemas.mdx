# Schemas

A schema is a named namespace inside your Centia.io database that groups [tables](./tables.mdx), views and [sequences](./sequences.mdx). Within one schema two tables cannot share a name, but the same table name can be reused in different schemas; `schema1.inductees` and `schema2.inductees` are distinct tables.

In Centia.io the schema is also the unit of ownership and addressing. Every [sub-user](../users.mdx) owns a schema named after itself, and several APIs are schema-qualified: the [SQL API](../statement.mdx) and [GraphQL](../graphql.mdx) resolve unqualified table names within a schema, and the [OGC services](../ogc/services.mdx) expose one endpoint per schema. The Schema API below creates, lists, renames and deletes schemas, and a new schema can be created together with nested table definitions in a single request.

## Add schema

A new schema object can be empty (name is the only property) or contain nested tables.

<Tabs>
    <TabItem value="webapp" label="Web App">
        ![Create schema in the Centia Web App](/img/screenshots/webapp-placeholder.svg)
    </TabItem>
    <TabItem value="http" label="HTTP" default>

        ```http request title="Create new empty schema"
        POST https://api.centia.io/api/v4/schemas HTTP/1.1
        Content-Type: application/json
        Authorization: Bearer abc123

        {
            "name": "rockhall"
        }
        ```

    </TabItem>
    <TabItem value="cli" label="CLI">

        ```bash
        centia schema add "rockhall"
        ```

    </TabItem>
</Tabs>

## Get schema

You can either get a single schema or a collection of schemas. The schema object contains all nested object like
tables, columns, indices and constraints. Use the `namesOnly` parameter to omit nested objects.

<Tabs>
    <TabItem value="webapp" label="Web App">
        ![View schemas in the Centia Web App](/img/screenshots/webapp-placeholder.svg)
    </TabItem>
    <TabItem value="http" label="HTTP" default>

        ```http title="All schemas, names only"
        GET https://api.centia.io/api/v4/schemas?namesOnly HTTP/1.1
        Accept: application/json; charset=utf-8
        Authorization: Bearer abc123
        ```

        ```http title="Specific schemas"
        GET https://api.centia.io/api/v4/schemas/rockhall,anotherschema HTTP/1.1
        Accept: application/json; charset=utf-8
        Authorization: Bearer abc123
        ```

    </TabItem>
    <TabItem value="cli" label="CLI">

        ```bash
        centia schema get "rockhall,anotherschema"
        ```

    </TabItem>
</Tabs>

## Rename schema

<Tabs>
    <TabItem value="webapp" label="Web App">
        ![Rename schema in the Centia Web App](/img/screenshots/webapp-placeholder.svg)
    </TabItem>
    <TabItem value="http" label="HTTP" default>
        ```http
        PATCH https://api.centia.io/api/v4/schemas/rockhall HTTP/1.1
        Content-Type: application/json
        Authorization: Bearer abc123

        {
            "name": "rock_roll_of_hall"
        }
        ```
    </TabItem>
    <TabItem value="cli" label="CLI">
        ```bash
        centia schema rename "rockhall" "myschema2"
        ```
    </TabItem>
</Tabs>

## Delete schema

:::danger
Be careful when deleting schemas - all nested objects will also be deleted!
:::

<Tabs>
    <TabItem value="webapp" label="Web App">
        ![Delete schema in the Centia Web App](/img/screenshots/webapp-placeholder.svg)
    </TabItem>
    <TabItem value="http" label="HTTP" default>
        ```http
        DELETE https://api.centia.io/api/v4/schemas/rock_roll_of_hall HTTP/1.1
        Authorization: Bearer abc123
        ```
    </TabItem>
    <TabItem value="cli" label="CLI">
        ```bash
        centia schema drop "rock_roll_of_hall"
        ```
    </TabItem>
</Tabs>
