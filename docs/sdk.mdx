# SDK

`@centia-io/sdk` is the official TypeScript/JavaScript client SDK for Centia.io. This page covers installation and the general behavior shared by all SDK classes — each feature is documented on the page for the API it wraps:

| Area | SDK classes/helpers | Documentation |
|---|---|---|
| Authentication | `CodeFlow`, `PasswordFlow` | [OAuth](./oauth) |
| Signup | `SignUp` | [Sub-users → Signup](./users#signup-browser--create-a-new-user) |
| SQL | `Sql`, `createSqlBuilder` | [SQL → Using the SDK](./statement#using-the-sdk) |
| JSON-RPC | `Rpc`, `createApi` | [Methods → Using the SDK](./methods#using-the-sdk) |
| GraphQL | `Gql` | [GraphQL → Using the SDK](./graphql#using-the-sdk) |
| Key/value store | `Keyvalue` | [Key/value store → Using the SDK](./keyvalue#using-the-sdk) |

Or from CDN:

```html
<script src="https://cdn.jsdelivr.net/npm/@centia-io/sdk@latest/dist/centia-io-sdk.umd.js"></script>
```

Requirements:
- Browser or Node.js 18+ (for global `fetch`).
- An accessible Centia.io host URL and client credentials.

ESM import:
```ts
import { CodeFlow, PasswordFlow, Sql, Rpc, Gql, Keyvalue, createApi } from "@centia-io/sdk";
import type { RpcRequest, RpcResponse, PgTypes } from "@centia-io/sdk";
```

## Authentication and token handling

The SDK handles token storage and refresh for you:

- Sign in once with one of the [OAuth flows](./oauth) — `CodeFlow` for browser apps (Authorization Code + PKCE) or `PasswordFlow` for trusted/CLI/server environments.
- Tokens and minimal options are saved to `localStorage` in browsers. In non-browser environments, an in-memory store is used for the lifetime of the process.
- Authorization headers are added automatically for all subsequent SDK requests.
- Access tokens are auto-refreshed when possible. If the refresh token is expired or missing, you'll get an error and should re-authenticate.

## Error handling

- Network/HTTP errors: thrown as `Error` with the status/body text when available.
- API errors from the newer classes (e.g. `Keyvalue`): thrown as `CentiaApiError` with `.status` and `.code`.

## Environment details

- Storage: tokens/options stored in `localStorage` when available; otherwise a global in-memory store is used (`globalThis.__gc2_memory_storage`).
- Fetch: Node.js 18+ recommended (includes native `fetch`). For older Node versions, add a Fetch polyfill.
